## 1. เทคโนโลยีและโครงสร้างโปรเจกต์

ให้ตรวจสอบไฟล์และโครงสร้างโปรเจกต์ปัจจุบันก่อนเริ่มเขียนโค้ด

หากยังไม่มีโปรเจกต์ ให้ใช้เทคโนโลยีที่เปิดใช้งานและสาธิตได้ง่ายบนเครื่องแข่งขัน โดยให้ความสำคัญกับ:

- HTML5 สำหรับโครงสร้าง
- CSS3 สำหรับการออกแบบ
- JavaScript สำหรับระบบคำนวณและประมวลผล
- ใช้ Local Dataset ไม่ต้องเชื่อมต่อ API ภายนอก
- ไม่จำเป็นต้องใช้ Backend หากไม่มีความจำเป็น

โครงสร้างไฟล์ที่แนะนำ:

- `index.html` – หน้าเว็บไซต์หลัก
- `css/style.css` – รูปแบบเว็บไซต์
- `js/app.js` – จัดการ Input และ UI
- `js/planner.js` – อัลกอริทึมวางแผนเที่ยว
- `js/validation.js` – ตรวจสอบ Input
- `js/data.js` – ข้อมูล Dataset ที่ผ่านการอ่านจากไฟล์ต้นฉบับ

เขียนโค้ดให้แยกหน้าที่ชัดเจน อ่านง่าย แก้ไขง่าย และไม่เขียนทุกอย่างรวมไว้ในไฟล์เดียว

## 2. Dataset – ต้องใช้ข้อมูลของผู้จัดเท่านั้น

ไฟล์ข้อมูลหลักคือ:

`Chiang_Rai_SmartTrip_Competition_Dataset.xlsx`

ภายในมี 3 Sheets ได้แก่

1. `Attractions`
2. `Travel_Time_Matrix`
3. `Rules_and_Sources`

ต้องอ่านและใช้ข้อมูลจากทั้ง 3 Sheets โดยตรง

ข้อกำหนด:

- สถานที่ท่องเที่ยวต้องเลือกจาก Attractions เท่านั้น
- ค่าใช้จ่ายต้องใช้ Demo_Cost_THB_Per_Person
- เวลาเที่ยวต้องใช้ Visit_Minutes
- เวลาเปิด–ปิดต้องใช้ข้อมูลจาก Dataset
- ประเภทสภาพอากาศต้องใช้ Weather_Type
- เวลาเดินทางต้องอ่านจาก Travel_Time_Matrix เท่านั้น
- ตรวจสอบกฎเพิ่มเติมจาก Rules_and_Sources
- ห้ามสร้างเวลาเดินทางเอง
- ห้ามใช้ระยะทางจริงจาก Google Maps แทน Matrix
- ห้ามเปลี่ยนตัวเลขใน Dataset เพื่อให้ระบบสร้างแผนได้ง่ายขึ้น

หากมีไฟล์ Excel ในโปรเจกต์ ให้ตรวจสอบและนำเข้าข้อมูลจริงโดยอัตโนมัติ สามารถแปลงข้อมูลเป็น JSON สำหรับการใช้งานแบบ Offline ได้

หากไม่มีไฟล์ Excel:
- ห้ามแต่ง Travel Time Matrix ขึ้นมาเอง
- ให้แสดงข้อความแจ้งว่า Dataset ยังไม่ครบ
- เตรียมระบบสำหรับนำเข้าไฟล์ Dataset ที่ถูกต้อง
- ห้ามแสดงแผนที่อ้างว่าเป็นผลลัพธ์จริงเมื่อไม่มีข้อมูล Matrix

## 3. Input Form – ระบบรับข้อมูลนักท่องเที่ยว

สร้างแบบฟอร์มที่สวยงามและใช้งานง่าย ประกอบด้วย:

**1. ความสนใจ (Interest)**

ให้เลือกได้อย่างน้อย 1 หมวด และรองรับการเลือกหลายหมวด

- Nature
- Culture
- Art
- Food

**2. งบประมาณต่อคน (Budget)**

- รับค่าตัวเลขเป็นบาทต่อคน
- ต้องไม่ติดลบ
- แสดงสัญลักษณ์ ฿
- แสดงงบประมาณที่เหลือหลังสร้างแผน

**3. เวลาท่องเที่ยว (Duration)**

- รองรับชั่วโมงและนาที
- แปลงเป็นหน่วยนาทีเพื่อใช้คำนวณ
- ต้องมากกว่า 0
- ต้องไม่เกินช่วงเวลาที่สามารถใช้งานได้จริง

**4. เวลาเริ่มต้น (Start Time)**

- ใช้รูปแบบ HH:MM
- ตรวจสอบรูปแบบเวลา 24 ชั่วโมง
- ต้องคำนวณเวลาถึงและเวลาออกจากสถานที่ได้อย่างถูกต้อง

**5. สภาพอากาศ (Weather)**

มี 2 ตัวเลือก:

- Normal
- Rain

**6. จำนวนผู้เดินทาง (Travelers)**

- ต้องเป็นจำนวนเต็ม
- ต้องมีค่าอย่างน้อย 1 คน
- คำนวณค่าใช้จ่ายรวมทั้งกลุ่มให้โดยอัตโนมัติ

เพิ่มปุ่ม `Generate My Trip` เพื่อสร้างแผนการท่องเที่ยว

เมื่อผู้ใช้แก้ไข Input ต้องสามารถคำนวณแผนใหม่ได้ทันที

## 4. Input Validation – ตรวจสอบข้อมูลอย่างสมบูรณ์

ต้องตรวจสอบข้อมูลก่อนประมวลผลทุกครั้ง

ตัวอย่างกรณีที่ต้องรองรับ:

- ไม่เลือกความสนใจ
- งบประมาณติดลบ
- กรอกเวลาไม่ถูกต้อง
- ไม่ระบุระยะเวลาท่องเที่ยว
- จำนวนผู้เดินทางเป็น 0
- จำนวนผู้เดินทางเป็นทศนิยม
- กรอกข้อความในช่องที่ต้องเป็นตัวเลข
- เวลาเริ่มต้นผิดรูปแบบ
- Dataset ไม่ครบ
- Matrix ไม่มีข้อมูลการเดินทางที่จำเป็น

แสดงข้อความแจ้งเตือนเป็นภาษาไทยอย่างชัดเจน โดยระบุว่าผู้ใช้ต้องแก้ไขอะไร

ห้ามปล่อยให้ระบบคำนวณด้วยข้อมูลผิดพลาด

## 5. Recommendation Engine – ระบบแนะนำสถานที่

สร้างอัลกอริทึมแนะนำสถานที่โดยใช้ข้อมูลจาก Attractions Dataset เท่านั้น

เงื่อนไข:

1. เลือกสถานที่ที่ตรงกับหมวดความสนใจที่ผู้ใช้เลือก
2. รองรับหลายความสนใจพร้อมกัน
3. ไม่เลือกสถานที่นอกหมวดที่ผู้ใช้สนใจ
4. ไม่เลือกสถานที่ซ้ำ
5. ต้องเริ่มต้นจาก F (หอนาฬิกาเชียงราย)
6. ต้องพิจารณางบประมาณ
7. ต้องพิจารณาเวลาท่องเที่ยว
8. ต้องพิจารณาสภาพอากาศ
9. ต้องพิจารณาเวลาเปิด–ปิด

**เงื่อนไขพิเศษของ Rain**

เมื่อเลือก Rain:

- ตัดสถานที่ที่ Weather_Type = outdoor ออกจากสถานที่ท่องเที่ยวที่สามารถเลือกได้
- สถานที่ที่ Weather_Type = indoor สามารถใช้ได้
- สถานที่ที่ Weather_Type = mixed สามารถใช้ได้
- F ต้องเป็นจุดเริ่มต้นของเส้นทางเสมอ โดยถือเป็นจุดตั้งต้น ไม่ใช่สถานที่ท่องเที่ยวที่ระบบแนะนำเพิ่มในวันที่ฝนตก

ห้ามใช้สถานที่ F เป็นข้ออ้างในการละเมิดกฎสภาพอากาศสำหรับสถานที่ท่องเที่ยวอื่น

**เป้าหมายของ Recommendation Engine**

เลือกสถานที่ที่ตรงกับความสนใจให้ได้มากที่สุดภายใต้ข้อจำกัดทั้งหมด

ถ้ามีหลายแผนที่เป็นไปได้ ให้ใช้หลักเกณฑ์ดังนี้:

1. จำนวนสถานที่ที่ตรงความสนใจมากที่สุด
2. จำนวนหมวดความสนใจที่ตอบโจทย์มากที่สุด
3. ใช้เวลารวมที่น้อยกว่า
4. ค่าใช้จ่ายต่อคนต่ำกว่า
5. ใช้ลำดับ ID เป็นเกณฑ์ตัดสินเมื่อยังเสมอกัน

ต้องอธิบายได้ว่าทำไมระบบถึงเลือกสถานที่เหล่านั้น

## 6. Route Optimization – ระบบจัดลำดับเส้นทาง

นี่คือหนึ่งในฟังก์ชันที่สำคัญที่สุด ต้องพัฒนาให้ถูกต้องตาม Travel_Time_Matrix

ระบบต้อง:

- เริ่มต้นจาก F เสมอ
- ใช้เวลาเดินทางจาก Matrix
- คำนวณการเดินทางระหว่างสถานที่แต่ละแห่ง
- จัดลำดับสถานที่ให้เหมาะสมที่สุด
- ห้ามเลือกสถานที่ซ้ำ
- ไม่จำเป็นต้องกลับมายัง F
- ไม่ใช้ระยะทางจริงจากแผนที่ออนไลน์

ให้ออกแบบอัลกอริทึมค้นหาเส้นทางที่เหมาะสม เช่น Exhaustive Search พร้อม Pruning หรือวิธี Optimization ที่เหมาะสมกับจำนวนสถานที่ใน Dataset

ห้ามใช้การสุ่มสถานที่แล้วนำมาแสดงเป็นคำตอบ

**สูตรการคำนวณ**

เวลาเดินทางรวม:

Travel Time = ผลรวมเวลาเดินทางของแต่ละช่วงจาก Matrix

เวลาเที่ยวรวม:

Visit Time = ผลรวม Visit_Minutes ของสถานที่ที่เลือก

เวลารอรวม:

Waiting Time = ผลรวมเวลาที่ต้องรอก่อนสถานที่เปิด

เวลารวม:

Total Time = Travel Time + Visit Time + Waiting Time

ต้องตรวจสอบว่าเวลารวมไม่เกินระยะเวลาที่ผู้ใช้กำหนด

## 7. Time & Opening Hours – คำนวณเวลาเปิด–ปิด

ต้องคำนวณเวลาอย่างถูกต้องสำหรับทุกสถานที่

สูตร:

เวลาไปถึงสถานที่ = เวลาออกจากสถานที่ก่อนหน้า + เวลาเดินทาง

หากไปถึงก่อนเวลาเปิด:

- ต้องรอจนถึงเวลาเปิด
- แสดงเวลารอ
- นำเวลารอไปรวมในเวลาท่องเที่ยวทั้งหมด

เวลาเริ่มเที่ยวสถานที่ = เวลาที่ไปถึง หรือเวลาเปิด หากต้องรอ

เวลาออกจากสถานที่ = เวลาเริ่มเที่ยว + Visit_Minutes

เงื่อนไข:

- ต้องไม่เริ่มเที่ยวก่อนเวลาเปิด
- ต้องออกจากสถานที่ไม่เกินเวลาปิด
- หากเวลาเที่ยวเกินเวลาปิด ต้องตัดสถานที่นั้นออกจากแผน
- ต้องคำนวณต่อเนื่องไปยังสถานที่ถัดไป
- ต้องนับเวลารอเข้าไปในระยะเวลารวม

สำหรับ F ให้ถือเป็นจุดเริ่มต้นของเส้นทาง ไม่คิด Visit_Minutes เป็นกิจกรรมท่องเที่ยวซ้ำอีกครั้ง และตรวจสอบเวลาเปิด–ปิดของจุดเริ่มต้นด้วย

แสดงเวลาในรูปแบบ HH:MM

## 8. Budget Calculation – ระบบคำนวณค่าใช้จ่าย

ใช้ข้อมูล Demo_Cost_THB_Per_Person เท่านั้น

สูตร:

ค่าใช้จ่ายต่อคน = ผลรวมค่าใช้จ่ายทุกสถานที่

ค่าใช้จ่ายทั้งกลุ่ม = ค่าใช้จ่ายต่อคน × จำนวนผู้เดินทาง

งบประมาณคงเหลือต่อคน = งบประมาณที่กำหนด - ค่าใช้จ่ายต่อคน

เงื่อนไข:

- ค่าใช้จ่ายต่อคนต้องไม่เกินงบประมาณ
- ต้องคำนวณค่าใช้จ่ายทั้งกลุ่ม
- ห้ามนำค่าใช้จ่ายรวมกลุ่มมาเทียบกับงบต่อคน
- ไม่รวมค่ารถ
- ไม่รวมค่าอาหารอื่น
- ไม่เพิ่มค่าใช้จ่ายที่ไม่มีใน Dataset

แสดงข้อมูลดังนี้:

- Budget per person
- Estimated cost per person
- Total group cost
- Remaining budget
- Budget usage percentage

## 9. Dynamic Replanning – ระบบปรับแผนใหม่

ต้องเป็นระบบที่คำนวณใหม่จริงทุกครั้ง ไม่ใช่เปลี่ยนเฉพาะข้อความที่แสดง

เมื่อเปลี่ยนค่าเหล่านี้ต้องประมวลผลใหม่:

- ความสนใจ
- งบประมาณ
- เวลาเที่ยว
- เวลาเริ่มต้น
- สภาพอากาศ
- จำนวนผู้เดินทาง

ระบบต้อง:

1. อ่าน Input ล่าสุด
2. ตรวจสอบความถูกต้อง
3. สร้างชุดสถานที่ที่เป็นไปได้ใหม่
4. ตรวจสอบสภาพอากาศ
5. คำนวณงบประมาณใหม่
6. คำนวณเวลาเปิด–ปิดใหม่
7. จัดลำดับเส้นทางใหม่
8. แสดงผลลัพธ์ใหม่

ห้ามใช้ผลลัพธ์จาก Input ก่อนหน้า

เพิ่มปุ่ม Reset เพื่อกลับไปยังค่าเริ่มต้น

เพิ่ม Preset สำหรับทดลองสาธิตอย่างน้อย 4 สถานการณ์ เช่น:

- Nature Trip
- Rainy Day Trip
- Low Budget Trip
- Food & Culture Trip

Preset ต้องเปลี่ยน Input จริงและเรียกอัลกอริทึมคำนวณใหม่ ไม่ใช่เลือกแสดงผลที่เขียนตายตัว

- เวลาเปิด–ปิด
- สภาพอากาศ

ต้องแสดง F เป็นจุดเริ่มต้นอันดับแรกเสมอ

ส่วนที่สาม: Why We Recommend This Trip

สร้างข้อความอธิบายว่า:

- ทำไมจึงเลือกสถานที่เหล่านี้
- สถานที่ตรงกับความสนใจอย่างไร
- ช่วยประหยัดงบประมาณอย่างไร
- เหตุใดจึงจัดลำดับเส้นทางแบบนี้
- แผนตอบสนองกับสภาพอากาศอย่างไร

ข้อความอธิบายต้องสร้างจากผลการคำนวณจริง ห้ามเขียนคำอธิบายแบบสุ่ม

## 11. No Plan Found – เมื่อไม่พบแผน

หากไม่มีแผนที่ตรงตามเงื่อนไข ต้องไม่แสดงแผนที่ผิดกฎ

ให้แสดงข้อความที่อธิบายสาเหตุ เช่น:

- งบประมาณไม่เพียงพอ
- ระยะเวลาท่องเที่ยวสั้นเกินไป
- ไม่มีสถานที่ตรงกับความสนใจ
- สถานที่ที่สนใจไม่เหมาะกับสภาพอากาศ
- ไม่สามารถจัดเส้นทางให้ทันเวลาเปิด–ปิด
- ข้อมูล Travel Time Matrix ไม่ครบ

เพิ่มคำแนะนำในการแก้ไขเงื่อนไข เช่น เพิ่มงบประมาณ เพิ่มเวลา หรือเปลี่ยนหมวดความสนใจ

หากทำได้ ให้แสดง Near-Miss Analysis ซึ่งเป็นตัวอย่างแผนที่เกือบผ่าน พร้อมระบุข้อจำกัดที่ทำให้ไม่สามารถนำมาใช้ได้จริง โดยต้องแยกชัดเจนว่าไม่ใช่แผนที่ผ่านเงื่อนไข

## 13. Creativity & Innovation

เพิ่มความสามารถที่สร้างความโดดเด่นเหนือเว็บแนะนำสถานที่ทั่วไป:

1. Smart Trip Score – คะแนนความเหมาะสมของแผนเที่ยว โดยอธิบายหลักเกณฑ์การให้คะแนน
2. Weather Adaptation – เปลี่ยนสถานที่ตามสภาพอากาศ
3. Budget Insight – วิเคราะห์การใช้งบประมาณ

6. Dynamic Trip Comparison – เปรียบเทียบผลลัพธ์ก่อนและหลังเปลี่ยน Input

ทุกความสามารถต้องมีการทำงานจริง ไม่ใช่มีเพียงข้อความหรือปุ่มที่กดแล้วไม่เกิดอะไรขึ้น
